这一稿真正要定的是什么

不是"多一个列表页"，也不是"把崩溃恢复做得更好看"。是"崩溃恢复"这个概念在项目化之后溶解掉了——项目本来就是一直自动保存的，所以没有"恢复"这个动作，也不该有"上次崩过"这种说法。这一稿把它删掉，换上一个真的读数（落盘失败）。

第二件事："素材找不到了"第一次有了出路。现在只能报告——fromSnapshot 移除片段、提示说一句"用到它的 4 个片段已移除"，然后就没有下一步了。这一稿给它一个出路，而且这个出路只存在于"打开项目"这一刻。

那一行标记为什么删掉了

这一稿的第一版在最近那张卡上画了「上次没正常结束，打开即接着」。那个标记的判据不存在。

现在之所以能说这句话，是因为单项目下"IndexedDB 里有一份带片段的快照"≈"上次留下了东西"。项目化之后快照就是项目本体——每个项目都永远有快照，那"没正常结束"拿什么判？要判就得加一个"正常离开时置位"的标志，而唯一能写它的时机是 pagehide，它在 iOS 上不一定来（autosave.ts 自己的注释就记着这件事）。于是标志会漏写，表现成"正常关闭也报崩过"——和现在一样，只是多了一个字段。假警告比没有警告更坏（D24）。

顺着这条查下去发现产品现在就在说一句假话：Editor.tsx 那条「上次的编辑没有正常结束」，判据只是 loadProject() 返回了非空，而正常关标签页同样会 pagehide 落盘——所以每次正常关掉再打开都会看到它。已随这一稿一起改成只陈述事实（「上次编辑到 X（N 个片段）」+「接着编」/「重新开始」），没等项目化落地，因为它是一句用户天天看得见的假话。

删掉它之后首页反而更诚实：加了标记的版本在暗示"有时候会丢"，而项目化之后的承诺恰恰是不会丢。3 分钟前 就是全部真相。

默认落在首页，而不是上次那个项目

会多一次点击，但 Resolve、Premiere、剪映、Figma 全都先给列表——项目多于一个的那天，"打开就是上次那个"会变成"我不知道我在编辑哪一个"。缓解办法是最近那个排第一、带黄铜描边、回车直接进。

它还给无引用数据的清理提供了一个合适的时机（首页＝这个标签里没有项目打开），但那不足以让清理变安全，见下一条。

清理不能只看"有没有人引用"，还要看年龄

第一版写的是"首页＝没有项目打开，所以扫全局引用是安全的"。那在一个标签里成立，两个标签就不成立：标签 A 正在编辑（刚导入一个素材，assets 已经写了、快照还没写），标签 B 回到首页点了清理——当场把 A 刚导入的那份删掉。project-store.ts 里那句 onblocked「被另一个标签占着」说明这个仓库知道多标签存在，而"入口互斥"那类做法在跨标签时拦不住。

所以判据是孤儿 + 够老：assets 记一个写入时间，只清"没人引用且写入超过一段时间"的。这是数据形状的改动，属于该在出稿阶段定下来的东西。另外清理只在用户明确点的时候做、并且先说清能清掉多少，不做后台自动 GC——误删的表现是"下次打开素材丢了"，而且不报错。

自动存盘的生命周期要跟着"当前项目"走

D23 那个三态（还在问／没有／有一份待表态）的存在理由是"必须等用户表态才能开自动存盘"。项目化之后没有"表态"这个动作了，三态塌成"项目装好了没有"的二态——但它守的那个陷阱没消失，只换了形态，而且多了一个更坏的。

一、autosave 不能在项目装进 store 之前开工，否则那个空时间轴会把项目覆盖成空的（和 D23 一字不差，只是"待恢复的快照"换成了"要打开的项目"）。

二、切项目必须先停再起，而且停之前那一次 flush 归旧项目。startAutosave() 订阅 store、把 timeline() 写进一个固定的键；键变成项目 id 之后，切换的那一瞬间 store 已经是新项目的时间轴而 autosave 还捏着旧项目的 id——防抖 1 秒内切完，写下去就是项目 A 的内容盖掉项目 B。D23 那条丢一份，这条串成两份都错，而且都不报错。

所以 CLAUDE.md 里那条纪律要改写而不是删掉：删掉的话第二种情形就没有任何东西拦着了。

离线素材永不进 EDL

看起来更自然的做法是给 MediaSource 加一个 offline 分支，片段留着、渲染成占位。不做。那要动合成层、导出层、reader、波形、代理——每一处都要回答"这一层没有画面怎么办"，而 resolveSource() 找不到就抛这条纪律正是 D23 立起来的护栏。

改成：打开项目时先验一遍读得动没有（isReadable 已经在做），读不动的停在指认页；用户指完或明确跳过，才把时间轴装进 store。于是 EDL 里永远只有能读的素材，下游一行都不用改。

指认页能显示"这个文件应该是 1920×1080 · 25fps · 1:12"，因为快照里的 SourceMeta 本来就存着这些——所以还能校验用户指错了文件（尺寸或时长不匹配就警告，但不阻止：也许他真的换了一版素材）。

跳过是破坏性的，所以要说出来。片段被移除之后历史是干净的（D23 理由 4：不存撤销栈），第一次编辑落盘就把这个状态写死了——撤销不回来。第一版脚注写的是"可以撤销回来"，那是错的，实测这一稿时才发现。

「指定文件…」走 <input type=file>，不依赖 showOpenFilePicker——导出侧"Safari 没有 picker"那条能力位经验在这里不适用：文件选取所有浏览器都有原生入口，缺的只是"往磁盘写"。

没有「保存」按钮，但有落盘失败态

自动存盘（防抖 1 秒 + 转后台立刻冲）已经在工作。加一个保存按钮会让用户以为不按就会丢，而实际上按不按都存——那是"两个真值来源"的界面形态。所以顶栏第二行说的是存盘状态，它是一个读数而不是一个动作。

失败态是这一行存在的全部理由。只会说「已保存 · 3 秒前」的话它是个恒为真的装饰，同 FontFaceSet.check() 那类假读数。而失败是真会发生的：配额满、隐私模式下 IndexedDB 不可用——lastPersistError() 早就记着原因，实测全仓库零个消费者，也就是说现在自动存盘可以静默失效、用户丢了编辑而完全不知道。这比"上次崩没崩"重要得多，而且它可知。

显眼度是选出来的：横幅 + 常驻读数两级并存。顶栏红字是常驻读数——失败是持续状态，常驻的问题要有常驻的读数；但数据丢失级别的警告不能只靠一行 10.5px 的小字。所以从"正常 → 失败"的沿上弹一条横幅（形态同 ed-recover，D23 验过不挤三栏），同一持续失败期内只弹一次——防抖 1 秒意味着失败每秒重演，按次弹就是风暴；写成功后横幅自动消失、顶栏回「已保存」，再失败算新的沿。这个状态机（正常/失败 × 弹过/没弹）是纯函数，可单测。不用弹窗（打断编辑），也不用 toast（会消失，而失败还在）。

文案不许说"改动不会被保住"。v2 就是这么写的，说过头了：flush 写的是整份 timeline 不是增量，失败期间的编辑都还在内存里，清出空间后下一次防抖写全部补上——只有关掉标签才真丢。说成永久丢失，用户会慌着关页面重开，那才是真丢。横幅要说的是"别关标签，清出来会自动接着存"。

失败分两类，出路不同（D24 的折叠回根因）。配额满是运行时出现的，走横幅，出路是清理——不把"导出成片保住成果"写成出路：Safari 没有 picker、导出走 OPFS 回退，配额满时那条路同样堵。隐私模式是从第一次写就注定的能力性事实，不该等用户编辑半天才说：进首页时就提示「这个窗口里项目不会被保存」，编辑器的横幅只兜"中途才坏"的情形。这个状态不另画，就是首页顶部一条提示。

钉住的判据：注入 saveProject 失败 → 横幅出现（带原因和出路）、顶栏变红；写成功一次 → 两者自动消失；同一失败期第二次失败不再弹；mock 掉 indexedDB → 首页就有提示，不等编辑。

存储读数：自己数；空态沉默

底部那行的数字全是自己记的账（快照序列化字节 + assets 里字体/LUT 逐项加总），不问 estimate()——同导出层"内存要自己数，不要问浏览器"：usage 会把 OPFS 导出残留混进来，总数和括号里的分项对不上账，而对不上账的读数比没有读数更坏。残留仍归导出面板的 .dlg-tidy 管：首页再报一次就是两处清理入口抢同一份数据，跨标签时还得把"够老"那道闸再抄一遍。

空态没有存储条。v2 画的是"本机可用空间 10.7 GB"，两个错：quota 不是磁盘空间（Chrome 给磁盘的一大截、Safari 另一种算法，跨浏览器语义不一致，必然被读成"磁盘剩多少"），而且一个字节都没存时根本没有读数可报——编一个数字比沉默更坏（D25）。quota 只出现在它本来就有用的两处：D24 的导出体检，和落盘失败横幅的解释文案（问不到就不带数字，同 D24"配额问不到整条跳过"）。

缩略图不进快照，按需抽

存进快照的话每次自动存盘都要从 GPU 读回一张图（toDataURL 是同步阻塞的），而落盘正是移动端最容易被系统杀掉的时刻。改成进首页时抽第一个视频片段的首帧——缩略图能力时间轴上已经在用（thumbnails.ts），复用就行。

但"抽不出来"不构成离线的证据。第一版写的是"抽不出来本身就是信号"——不对，抽不出来还可能是解码失败，把两者混成同一个斜纹底就是把派生现象当读数（D24 那条）。离线由 isReadable 判（读 1 字节，便宜且准），缩略图不参与。斜纹底只表示"没有缩略图"这一件事。纯图片项目和纯音频项目退回类型图标。

抽出来的位图加一层会话内的内存缓存（Map<projectId, ImageBitmap>，照例挂 dev 全局——模块级单例那条纪律），同会话回到首页不重抽。不落盘：持久缓存需要一套失效判据（素材换了、第一个片段挪了怎么办），等真在移动端多项目卡了再说。

这一项会怎么静默出错，拿什么钉住

这一稿的第一版通篇在讲界面，一句没写这个——而前两项（D35 / D36）每一条决策都是从"它坏掉时长什么样"倒推出来的。项目管理主要是状态与存储，所以取舍应该像 project-snapshot.ts 那样全收进纯函数（那里能脱离浏览器单测），IndexedDB 那层只存取。四个形态：

  • 切项目串写（上面第二条）。判据：切到 B 编一下、再切回 A，A 的内容逐字段不变。这条必须有，它是最可能的真 bug。
  • 清理误删还在用的 asset。表现是下次打开项目素材丢了、片段被移除，而全程不报错。判据是纯函数级的："引用集合"要从所有项目算出来（漏一个项目就删一批），以及"够老"那道闸真的拦住了刚写入的。
  • 指认页把 X 的文件指给了 Y。画面全错而不报错。判据：指认结果按 sourceId 配对、不按顺序配对（列表可以排序，顺序不是身份）。尺寸／时长不匹配的警告是给用户的，不是护栏。
  • 制作副本时两个项目共享 sourceId——这是对的（File 是引用，复制毫无意义），但它意味着"删掉副本"绝不能顺手删 assets。判据：删项目之后，原项目的素材还在。

另外有一条只能靠界面实测的：进首页要对每个项目的每个素材验 isReadable，那是 N×M 次读。项目多了会卡在首屏，所以它必须是惰性的（卡片各自异步填），而"异步填"又踩过一次坑——D36 里检查器那行解码尺寸就是因为读异步缓存而实际上看不见。这里同理：先渲染卡片、离线标记后到，不能等它。

项目名：自动取名只做一次

Timeline 要加 name 字段（现在顶栏显示的是 sources[0]?.name，那是个凑出来的代理，重命名无处可存）。新建叫「未命名项目」，导入第一个素材时自动用素材名——但用户重命名过之后就不再自动。少这个条件的表现是"我改了名字，导入一个素材，名字被改回去了"。所以它需要一个"名字是不是用户给的"的标志，而不是靠"名字等不等于素材名"去猜。

改了 Timeline 的形状就要给 SNAPSHOT_VERSION +1（4 → 5）。

这一稿明确没有画

  • 项目模板 / 预设分辨率选择器。新建就是空的 1920×1080 · 30，改分辨率在导出面板里已经有了。
  • 项目文件的导入导出（.kerf）。它要回答"素材怎么一起走"，而那是一个独立的大问题（打包？相对路径？），不该塞进这一项。
  • 搜索 / 标签 / 文件夹。本机项目数量是个位数，搜索框是纯装饰。
  • 缩略图自选帧。要一个"设为封面"的入口和一个存的地方，而首帧已经够认。
  • 回收站。删除给一次确认（写明片段数），删了就是删了。留着要处理"素材还被回收站里的项目引用着"，把 GC 的规则复杂化一倍。
